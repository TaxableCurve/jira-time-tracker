# Electron Desktop App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wrap the existing Next.js app in an Electron shell to produce installable desktop apps for Windows, macOS, and Linux, with auto-updates via GitHub Releases.

**Architecture:** Electron's Main Process spawns a Next.js standalone server on a free local port, waits for it to respond, then opens a BrowserWindow pointing at that URL. The renderer is sandboxed (`contextIsolation: true`, `nodeIntegration: false`). All Jira API calls continue to go through the existing Next.js API Routes — no changes to app code.

**Tech Stack:** Electron, electron-builder, electron-updater, concurrently, wait-on, TypeScript (separate tsconfig for the Electron layer), GitHub Actions for CI/CD.

> **Why a separate tsconfig?** The root `tsconfig.json` uses `"module": "esnext"` and `"moduleResolution": "bundler"` for Next.js. Electron's main process runs in a Node.js CommonJS environment — it needs `"module": "commonjs"`. The two configs are incompatible so we keep them separate.

- [ ] **Step 1: Create `tsconfig.electron.json`**

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "commonjs",
    "lib": ["ES2020"],
    "outDir": "electron/dist",
    "rootDir": "electron",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "resolveJsonModule": true
  },
  "include": ["electron/**/*.ts"],
  "exclude": ["node_modules"]
}
```

> **How electron-updater works:** It reads a `latest.yml` file from your GitHub Release to check if a newer version exists. If yes, it downloads the installer in the background and installs it when the app closes. You configure this in electron-builder's `publish` section (already done in Task 1). The `GH_TOKEN` secret in GitHub Actions authorizes electron-builder to upload the `latest.yml` and installers.

- [ ] **Step 1: Create `electron/updater.ts`**

```ts
import { autoUpdater } from 'electron-updater'
import { dialog } from 'electron'

export function initUpdater(): void {
  autoUpdater.autoDownload = true
  autoUpdater.autoInstallOnAppQuit = true

  autoUpdater.on('update-available', () => {
    dialog.showMessageBox({
      type: 'info',
      title: 'Update available',
      message: 'A new version of Jira Time Tracker is downloading in the background. It will install when you close the app.',
      buttons: ['OK'],
    })
  })

  autoUpdater.on('error', (err) => {
    console.error('[updater] error:', err.message)
  })

  autoUpdater.checkForUpdatesAndNotify()
}
```

## Task 6: Create electron/main.ts

**Files:**
- Create: `electron/main.ts`

> **Electron process model:** Your app has two types of processes. The **Main Process** (`main.ts`) is a Node.js process — it has full system access and manages windows. The **Renderer Process** is the browser window — it runs the web page (your Next.js app) in a Chromium sandbox. They communicate via IPC. Your `main.ts` is the entry point: Electron calls it when the app starts.

> **`ELECTRON_RUN_AS_NODE`:** To run the Next.js server, we spawn a child process using the Electron binary itself with this env var set to `'1'`. This makes Electron behave as a plain Node.js runtime, which is needed because Electron doesn't expose a separate Node binary.

- [ ] **Step 1: Create `electron/main.ts`**

```ts
import { app, BrowserWindow, ipcMain } from 'electron'
import { spawn, ChildProcess } from 'child_process'
import * as path from 'path'
import * as net from 'net'
import * as http from 'http'
import { initUpdater } from './updater'

const isDev = process.env.NODE_ENV === 'development'
let nextServer: ChildProcess | null = null
let mainWindow: BrowserWindow | null = null

function findFreePort(): Promise<number> {
  return new Promise((resolve, reject) => {
    const server = net.createServer()
    server.listen(0, '127.0.0.1', () => {
      const addr = server.address() as net.AddressInfo
      server.close(() => resolve(addr.port))
    })
    server.on('error', reject)
  })
}

function waitForServer(url: string, timeoutMs = 30_000): Promise<void> {
  return new Promise((resolve, reject) => {
    const deadline = Date.now() + timeoutMs
    const attempt = () => {
      http.get(url, (res) => {
        if (res.statusCode === 200) {
          resolve()
        } else {
          retry()
        }
        res.resume()
      }).on('error', retry)
    }
    const retry = () => {
      if (Date.now() >= deadline) {
        reject(new Error(`Next.js server did not start within ${timeoutMs}ms`))
        return
      }
      setTimeout(attempt, 500)
    }
    attempt()
  })
}

async function startNextServer(): Promise<number> {
  if (isDev) {
    // In dev, Next.js is already running via `concurrently` in electron:dev
    return 3000
  }

  const port = await findFreePort()
  const serverPath = path.join(app.getAppPath(), '.next', 'standalone', 'server.js')

  nextServer = spawn(process.execPath, [serverPath], {
    env: {
      ...process.env,
      ELECTRON_RUN_AS_NODE: '1',
      PORT: String(port),
      HOSTNAME: '127.0.0.1',
      NODE_ENV: 'production',
    },
    stdio: 'pipe',
  })

  nextServer.stdout?.on('data', (d) => process.stdout.write(`[next] ${d}`))
  nextServer.stderr?.on('data', (d) => process.stderr.write(`[next] ${d}`))
  nextServer.on('exit', (code) => console.log(`[next] exited with code ${code}`))

  await waitForServer(`http://127.0.0.1:${port}/api/health`)
  return port
}

function createWindow(port: number): void {
  mainWindow = new BrowserWindow({
    width: 1280,
    height: 800,
    minWidth: 900,
    minHeight: 600,
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
      contextIsolation: true,
      nodeIntegration: false,
    },
  })

  mainWindow.loadURL(`http://127.0.0.1:${port}`)
  mainWindow.on('closed', () => { mainWindow = null })
}

app.whenReady().then(async () => {
  ipcMain.handle('app:version', () => app.getVersion())

  try {
    const port = await startNextServer()
    createWindow(port)
    if (!isDev) initUpdater()
  } catch (err) {
    console.error('Failed to start:', err)
    app.quit()
  }
})

app.on('window-all-closed', () => {
  nextServer?.kill()
  app.quit()
})

// macOS: re-open window when clicking dock icon with no windows open
app.on('activate', () => {
  if (mainWindow === null) {
    startNextServer().then(createWindow).catch(() => app.quit())
  }
})
```

## Task 11: Create GitHub Actions release workflow

**Files:**
- Create: `.github/workflows/release.yml`

> **How the release flow works:** When you push a git tag starting with `v` (e.g., `v1.6.0`), this workflow runs on three runners simultaneously (Windows, macOS, Linux). Each runner builds the app for its platform and uploads the installer + `latest.yml` to a new GitHub Release. Existing users with the app open will receive an update notification on next launch.

> **`GITHUB_TOKEN`:** GitHub Actions provides this automatically — no manual secret setup needed for publishing releases. It's available as `secrets.GITHUB_TOKEN`.

- [ ] **Step 1: Create `.github/workflows/release.yml`**

```yaml
name: Release

on:
  push:
    tags:
      - 'v*'

jobs:
  build-linux:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - name: Install dependencies
        run: npm ci
      - name: Build and publish
        run: npm run electron:dist
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

  build-macos:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - name: Install dependencies
        run: npm ci
      - name: Build and publish
        run: npm run electron:dist
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

  build-windows:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - name: Install dependencies
        run: npm ci
      - name: Build and publish
        run: npm run electron:dist
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## Notes for future migration to Option B (IPC native)

When you're ready to remove the embedded server:

1. Replace each `app/api/jira/*/route.ts` with an `ipcMain.handle('jira:*', handler)` in `electron/main.ts`
2. Replace each `fetch('/api/jira/*')` in the frontend with `window.electronAPI.jira.*()` calls via `preload.ts`
3. Switch `next.config.ts` to `output: 'export'` and remove the server spawn from `main.ts`
4. Remove `electron-updater` health check dependency on the server

Each API route can be migrated independently — no big-bang rewrite needed.
